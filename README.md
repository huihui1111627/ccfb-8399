# 股权穿透分析系统

企业征信场景下的股权穿透工作台：导入工商登记/变更数据 → 主体消歧 → 股权图谱 →
实际控制人与受益所有人识别 → 历史时点回看 → 与独立基准比对准确率。

TypeScript 编写，Node 运行，浏览器控制台为原生 TypeScript + SVG（esbuild 打包），
无前端框架依赖。

## 快速开始

```bash
npm install
npm run build          # 打包前端 + 编译服务端（dist/、public/app.js）
npm start              # http://localhost:8399
```

打开页面前先在控制台点「载入演示数据」，或直接调用接口：

```bash
curl -X POST http://localhost:8399/api/import/demo
```

演示数据已随仓库提供（`data/samples/`），基准数据在 `data/truth/`。
如需从零重建：

```bash
npm run dataset        # 生成 CSVs + record_map.json（模拟真实脏数据）
npm run ground-truth   # 用独立算法生成真值（集群 + 实控人）
npm test               # 18 + 12 个引擎/服务测试
```

## 页面功能

| 页面 | 能力 |
| --- | --- |
| 1 数据导入 | 三类 CSV 上传（拖拽/选择），逐字段映射可改，中英文表头切换，导入流水与数据质量提示 |
| 2 主体消歧 | 企业按统一社会信用代码/曾用名归并；同名自然人按证件片段、任职、地址聚类；证据链可查；支持人工合并/拆分与撤销 |
| 3 股权图谱 | SVG 力导向分层图，滚轮缩放、拖拽平移、双击聚焦；边宽映射持股比例；点击节点显示穿透路径与环路 |
| 4 实控人与变更历史 | 实控人判定（自然人/一致行动组/无实控人）、受益所有人清单、一致行动与代持人工补录、任意历史时点回看、CSV 导出 |
| 5 准确率评估 | 与 `data/truth` 独立基准比对：B³ 精确率/召回率/F1、实控人准确率、受益所有人 F1、逐条差异 |

## 核心算法

### 1. 主体消歧（`src/core/resolve.ts`）

企业：
1. 统一社会信用代码相同 → 并查集合并；
2. 变更记录中的「名称变更」把曾用名与现名连边；
3. 无统一代码的记录按「名称一致 / 核心名一致 + 地址一致 / 简称前缀 + 地址一致」挂接；核心名会剥离城市前缀与「有限公司」等后缀。

自然人分两阶段，先按**规范化姓名**分组，再在组内聚类：

| 证据 | 权重 | 说明 |
| --- | --- | --- |
| 证件号（掩码按通配位比较）完全一致 | 1.0 | 立即合并 |
| 前 6 位 + 后 4 位一致 | 0.90 | 同地区同尾号 |
| 仅后 4 位一致 | 0.35 | 弱证据，不会单独合并 |
| 任职企业 + 职务均相同 | 0.82 | |
| 同企业任职 | 0.60 | |
| 股东地址相同 | 0.60 | 注册地址常被复用，仅作辅助 |
| 同名 | 0.30 | **仅弱先验，不会单独合并** |

冲突优先：证件号存在冲突位（且非掩码）时**强制禁止合并**，即使姓名、地址、任职全部相同 —— 这是防同名误并的核心。演示数据里 4 个「王海峰」正是靠这一点保持独立；其中一个与另一个同名且同地址，仅证件尾号不同。

### 2. 穿透持股（`src/core/ownership.ts`）

有效的穿透比例定义为

```
U = D · (I − C)⁻¹
```

- `C[i][j]` = 企业 i 持有企业 j 的比例，`D[p][j]` = 自然人 p 直接持有企业 j 的比例；
- 展开后即「所有股权路径的持股比例连乘再求和」；
- 只要每列直接持股之和 ≤ 1（真实工商数据必然成立），`I − C` 可逆，**循环持股与交叉持股不会发散**，得到唯一稳定解；
- 提供两个独立求解器：
  - `solveLinear`：高斯消元（部分主元），用于生产结果；
  - `solveIterative`：固定点迭代，返回收敛轨迹，用于展示「环路不会死循环」；
- `findCycles` 用 Tarjan SCC 找出交叉持股组，图上前端以红色虚线标记；
- `enumeratePaths` 逐路径枚举并输出「环路截断残值」，解释某一比例由哪些链路构成；
- 同一 (公司, 股东) 有多期记录时，只取 as-of 日期之前最新的一条；列和不为 1 时归一化并在诊断中报告。

演示数据包含两组环：
- `蓝海科技 ⇄ 星海控股`（互相持股）；
- `启明汇投 → 中原控股 → 启明投资 → 启明汇智` 三节点环。

### 3. 实际控制人（`src/core/controllers.ts`）

1. 受益所有人：代持还原后穿透持股 **严格 > 25%** 的自然人；
2. 实控人：单一自然人 ≥ 30%，或一致行动组合计 ≥ 30% 且高于任一单一股东；
3. 都不满足时判定「无实际控制人（股权分散）」，同时给出最高持股人供复核。

代持关系通过 `applyNominees` 把名义持有人的份额转移到实际出资人名下，并保留 `legalPct`（名义登记比例）用于对照。一致行动关系按生效/失效日期过滤。

### 4. 历史时点

所有权与人工关系都带生效日期；`buildGraph(rows, entities, relations, { asOf })` 在每个时点重建当期图并重新求解，因此历史回看不是「按最新结构反推」，而是真正使用当期有效的数据。

## 测试数据与基准

`tools/scenario.py` 是测试场景的唯一作者来源（应用本身不引用它）：

- 20 家企业，含 3 家噪声公司（蓝海贸易、星海传媒、启明生物）+ 1 家同名但无关的「海峰投资」；
- 14 名自然人，其中 4 人同名「王海峰」，靠证件片段区分；另有 1 人与他人**同名且同地址**，仅证件不同；
- 覆盖多层嵌套、环状/交叉持股、代持、一致行动、名称/地址/实控人变更；
- 三个快照（2019-01-01 / 2022-06-30 / 2025-12-31）对应的真实实控人单独存放在 `data/truth/controllers.json`。

生成的两条独立链路保证基准不是「自己验自己」：

1. `scripts/generate-dataset.ts` 把场景渲染成**脏 CSV**（名称写法 4 种、比例 3 种格式、日期 2 种格式、缺失字段、同名干扰），同时输出每条记录真实归属的 `data/truth/record_map.json`；
2. `tools/build_ground_truth.py` 采用**稠密矩阵求解**（`numpy.linalg.solve`）独立计算穿透比例与实控人，写入 `data/truth/controllers.json`。应用侧使用图传播/高斯消元，两条实现互不共享代码。

`/api/evaluate` 按记录比对主体归并（B³），并按时点比对实控人与受益所有人清单。当前演示数据的结果：B³ F1 = 100%，实控人准确率 = 100%，受益所有人 F1 = 100%（60 个「企业 × 时点」样本）。任何算法回归都会立即在页面 5 与 `npm test` 中暴露。

## 设计取舍

- **不用图数据库/前端框架**：20 家企业、百余条记录的场景下，内存图与原生 SVG 足够快，也便于审计每一个数值的来源；
- **数据永远可追溯**：每个主体保留 `recordIds` 与归并证据，图上每条边保留来源记录 ID 与数据来源；
- **人工可覆盖、可撤销**：合并/拆分/关系补录不修改原始 CSV，而是作为规则参与下次消歧，撤销后完全恢复；
- **比例不强行凑整**：工商数据列和可能不等于 1（如增资未同步），系统归一化并显式告警，而不是静默接受；
- **导出即审计底稿**：受益所有人 CSV 同时给出穿透比例与名义登记比例、实际控制人、判定依据与基准日。
